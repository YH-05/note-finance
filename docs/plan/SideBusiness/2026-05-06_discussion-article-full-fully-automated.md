# 議論メモ: /article-full コマンドの完全自動化

**日付**: 2026-05-06
**参加**: ユーザー + AI
**対象ファイル**: `.claude/commands/article-full.md`

## 背景・コンテキスト

`/article-full` は記事作成の全工程（初期化→リサーチ→ドラフト→批評→投稿）を一括実行する統合コマンドだったが、各 Phase の境界に **ヒューマンフィードバック（HF）承認ステップ** が組み込まれており、無人実行ができなかった。

| HF番号 | 位置 | 内容 |
|--------|------|------|
| HF1 | Phase 1 後 | トピック承認 (y/n) |
| HF3 | Phase 2 後 | 主張採用確認 (y/n) |
| HF5 | Phase 3 後 | 初稿レビュー (y/n) |
| HF6 | Phase 4 後 | 最終確認（承認/修正） |

`--skip-hf` オプションは存在したが「非推奨」扱いで、ドキュメントもそれを前提に書かれていた。
ユーザーは「途中の HF で承認不要にして、完全に自動で一気通貫で作業するように変更したい」と要望。

## 議論のサマリー

- HF を残す価値（品質保証）vs 完全自動の価値（無人実行・スループット）のトレードオフ
- → 批評（critique）プロセスで自動的にコンプライアンス・事実正確性を検証しているため、HF を全廃しても最低限の品質は担保できる
- クリティカル違反（コンプライアンス fail / 投稿失敗等）でのみ自動中断する設計に統一

## 決定事項

1. **HF1/HF3/HF5/HF6 を全廃** し、デフォルトで完全自動実行モードに変更
2. **`--skip-hf` オプションを廃止**（デフォルトが自動実行になったため不要）
3. **対話入力（トピック名・カテゴリ・スラッグ・カテゴリ別追加情報）を全て自動補完**
   - 引数 → 自動推定 → デフォルト値の優先順で補完
   - カテゴリ未指定時は finance-article-writer の judge_category で自動推定
4. **エラーハンドリングを再設計**
   - 継続可能（warning）: カテゴリ推定失敗・一部ソース失敗・低スコア → 警告のみで続行
   - クリティカル中断: トピック特定不可・コンプライアンス fail・note.com 投稿失敗 → 中断＋再開コマンド案内
5. **進捗ログのみ出力**: 各 Phase 完了時に `[Phase N 完了] ... → Phase N+1 へ自動継続...` を表示
