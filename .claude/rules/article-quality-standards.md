# 記事品質ルール（note.com 向け）

記事執筆・批評・修正に関わる全エージェント・スキル・コマンドが遵守すべきルール。

## ルール1: マークダウン表は必ず画像化する

note.com ではマークダウン表が正しくレンダリングされないため、**記事内の全てのマークダウン表を `/generate-table-image` スキルでPNG画像に変換**し、画像参照で埋め込むこと。

### 手順

1. 表データのJSONを作成（`.tmp/table_*.json`）
2. `uv run --with playwright python scripts/generate_table_image.py` で画像生成
3. 出力先: `articles/{category}/{slug}/images/table_*.png`
4. 記事内で `![表タイトル](images/table_*.png)` として参照

### 画像化の閾値

以下のいずれかを満たす表は**必ず画像化**する:

- **列数 3以上**
- **行数 5以上**（ヘッダを除くデータ行）

両方未満の小さな表（2列×4行以下）はマークダウンのまま残してよい。note.com で「本当に小さな表」をわざわざ画像化すると可読性が落ちるため。

### 適用タイミング

| フェーズ | 対応 |
|---------|------|
| article-draft | ドラフト生成時に表があれば画像化 |
| article-critique | Step 4.4（画像ポストプロセス）で自動検出・画像化 |
| article-publish | Step 1.5 で残存表を検出、閾値超過なら投稿中止 |
| revised_draft 生成 | 修正版で表が追加された場合も画像化 |

## ルール2: 参考文献・引用ソースは「独立段落のURL」で貼る（note.comリンクカード化）

数値データ・統計・専門家の見解・レポート等を引用する箇所には、**引用段落の直後に「URLのみの独立段落」を挿入**してソースを明示すること。note.com は単独段落のURLを自動的にリンクカードとして埋め込み表示する（参考: [テキスト記事に埋め込みできるサービス一覧 – noteヘルプ](https://www.help-note.com/hc/ja/articles/360019596133)）。

### ⚠ 重要な制約: マークダウンリンク `[text](url)` は使用禁止

`[テキスト](URL)` 形式のインラインマークダウンリンクは、note.com 投稿パイプライン（`scripts/note_publisher/markdown_parser.py::_strip_inline_markdown`）が**プレーンテキストに変換しURLを完全に除去**する。よってマークダウンリンクは note.com 上で機能しない。

❌ 禁止例（投稿時にURLが消える）:
```markdown
純資産総額が[10兆2,846億円に到達](https://example.com/source)しました。
```
→ 投稿後の表示:「純資産総額が10兆2,846億円に到達しました。」（URLは消失）

### ✅ 推奨フォーマット（カード表示される唯一の方法）

引用段落の **直後に空行 → URL単独段落 → 空行 → 次段落** の構造で配置する:

```markdown
マッキンゼーのレポートによると、生成AI市場は2030年までに年率40%で成長し、世界経済への寄与額は2.6〜4.4兆ドルに達する見込みです。

https://www.mckinsey.com/capabilities/quantumblack/our-insights/the-economic-potential-of-generative-ai-the-next-productivity-frontier

一方、ガートナーの分析では...
```

### note.com でカード化される条件

- URL の **前後に他の文字を含めない**（句読点・空白も不可）
- URL を **段落として独立**させる（マークダウン上は前後に空行）
- 短縮URL（`bit.ly` 等）や note.com 非対応サービスは**カード化されずテキストリンクにフォールバック**するため、可能な限り **オリジナルの長いURL**を使う
- 同じ段落に1つだけ。複数URLを1段落に並べると自動埋め込みは動作しない

### 必須リンク対象

引用元として URL 段落を必ず付ける対象:

- 具体的な数値データ（純資産総額、リターン、比率、市場規模など）
- 統計・調査・レポートの引用（マッキンゼー、ガートナー、IMF等のレポート）
- 専門家・機関の見解の引用
- 公式発表・プレスリリース・決算資料の参照
- 学術論文・ニュース記事の引用

### 配置パターン

```markdown
<!-- パターンA: 引用直後（推奨・標準） -->
マッキンゼーのレポートによると、AI投資は年率40%で成長する見込みです。

https://www.mckinsey.com/example/report

次の論点は...

<!-- パターンB: 複数の文を引用してから末尾にまとめて貼る場合 -->
ガートナーは2026年のクラウド支出を6,750億ドルと予測しました。前年比21.5%増です。
パブリッククラウドの中ではSaaSが最大カテゴリで、2,990億ドルに達します。

https://www.gartner.com/en/newsroom/press-releases/2026-example

<!-- パターンC: 1段落で複数ソースを引用する場合は段落を分ける -->
IMFは世界成長率を3.2%と予測しています。

https://www.imf.org/en/Publications/WEO/example

一方、世界銀行は2.7%とより慎重な見方を示しています。

https://www.worldbank.org/en/publication/global-economic-prospects/example
```

### 適用タイミング

| フェーズ | 対応 |
|---------|------|
| article-research | リサーチノートにソースURL（短縮していないオリジナルURL）を必ず記録 |
| article-draft | 引用箇所の直後にURL単独段落を挿入。`[text](url)` 形式は使わない |
| article-critique | (1) マークダウンリンクが残っていないか (2) 引用箇所にURL段落があるか をチェック |
| article-publish | `markdown_parser` が URL 段落をそのまま `paragraph` ブロックとして note.com に転送する（特別な処理は不要） |
| revised_draft 生成 | 不足しているURL段落の補完。残存マークダウンリンクの段落分離変換 |

## ルール3: チャートは `/generate-chart-image` で画像化する

記事内でデータの可視化（折れ線グラフ、棒グラフ、散布図、ヒートマップ等）が必要な場合、**`/generate-chart-image` スキルでPNG画像を生成**し、画像参照で埋め込むこと。

### 手順

1. チャートデータのJSON定義またはプリセットを用意
2. `/generate-chart-image` スキルで matplotlib + seaborn レンダリング
3. 出力先: `articles/{category}/{slug}/images/chart_*.png`
4. 記事内で `![チャートタイトル](images/chart_*.png)` として参照

### 使用場面

- 時系列データの推移（株価、純資産総額、リターン推移など）
- 比較データの可視化（パフォーマンス比較、資産配分の円グラフなど）
- 週次レポートのチャート生成
- 資産シミュレーションのグラフ作成

### 適用タイミング

| フェーズ | 対応 |
|---------|------|
| article-research | 可視化すべきデータを特定 |
| article-draft | ドラフト生成時にチャート画像を生成・埋め込み |
| article-critique | 「チャートで表現すべきデータがテキストのままになっていないか」をチェック |
| revised_draft 生成 | 不足しているチャートを補完 |

## チェックリスト（批評・最終確認用）

- [ ] マークダウン表が記事内に残っていないか（全て画像化済みか）
- [ ] 引用箇所の直後に **URL単独段落** が配置されているか
- [ ] **マークダウンリンク `[text](url)` が記事内に1件も残っていないか**（投稿時に剥がれるため禁止）
- [ ] URL段落の前後に他の文字（句読点・空白等）が混入していないか
- [ ] URLリンクは有効か（壊れたリンクがないか）
- [ ] 短縮URL（bit.ly等）ではなくオリジナルの長いURLになっているか
- [ ] チャートで表現すべきデータがテキストのままになっていないか
- [ ] 画像ファイル（表・チャート）が `images/` ディレクトリに存在するか
