# ライター規約準拠 評価基準

finance-article-writer スキルが定義する執筆ルール（common-rules.md + カテゴリ別ルール）への準拠を検証する。
既存の5批評エージェント（fact, compliance, structure, data, readability）がカバーしない項目に限定する。

---

## 0. タイトル品質チェック (WR-TL)

共通ルール common-rules.md § 3「タイトル生成ルール」への準拠を検証する（earnings カテゴリは固定フォーマットのため適用除外）。

### 検査項目

| 項目 | 判定基準 | severity |
|------|---------|---------|
| 具体性 | 「市場動向について」等の抽象タイトルでないか。企業名・制度名・指標名のいずれかが含まれるか | medium |
| 読者メリット | 「分かる・学べる・比較・解決」のいずれかが含意されているか（数字や「比較」「理解」「シミュレーション」等のキーワード） | medium |
| 文字数 | 全角30-38字以内に収まっているか | low（超過） |
| 禁止記号 | ダッシュ記号（`ーー` `——` `—` `--`）が含まれていないか | high（検出時は修正必須） |
| 煽り記号 | `！！！` `？？？` の連打がないか | medium |
| 投資助言的断定 | 「絶対儲かる」「必ず上がる」等の断定表現がないか | high |

### 検証フロー

1. `meta.yaml` の `title` フィールドまたは本文先頭の `# ` 見出しを取得
2. `category == earnings` の場合は固定フォーマット `【🇺🇸米株決算】{企業名}（{ティッカー}）Q{数字} {年} 決算プレビュー/レビュー` に一致するかのみ判定
3. それ以外は上記検査項目を順次チェック
4. 問題があれば writer_rules.issues に `rule_id: WR-TL-xxx` として記録

---

## 1. 文字数チェック (WR-WC)

カテゴリ別の文字数範囲。フロントマター・参考データソース・ディスクレーマーを除いた本文の文字数を計測する。

| カテゴリ | 最低 | 最大 |
|---------|------|------|
| stock_analysis | 4000 | 6000 |
| macro_economy | 3000 | 5000 |
| investment_education | 3000 | 5000 |
| quant_analysis | 4000 | 6000 |
| market_report | 3000 | 5000 |
| asset_management | 2000 | 4000 |

**severity**:
- 最低未満 or 最大超過 → **high**
- 最低の90%未満 or 最大の110%超過 → **high**（大幅逸脱）
- 最低の90-100% or 最大の100-110% → **medium**（境界域）

## 2. 必須セクションチェック (WR-SC)

カテゴリ別の必須セクション（見出し）の存在と順序を検証する。

### stock_analysis

```
1. エグゼクティブサマリー (200-300字)
2. 企業概要
3. 財務分析
4. テクニカル分析
5. リスク要因
6. まとめ
7. 参考データソース
```

### macro_economy

```
1. 概要 (200-300字)
2. 背景・経緯
3. 分析 (複数の分析軸)
4. 今後の見通し
5. 投資家への示唆
6. まとめ
7. 参考データソース
```

### investment_education

```
1. はじめに (200-300字)
2. {テーマ}とは (500-800字)
3. なぜ重要なのか (300-500字)
4. 実践ガイド (ステップ1-3)
5. よくある疑問（FAQ）(3-5個)
6. 注意点・リスク (300-500字)
7. まとめ (200-400字)
8. 参考データソース
```

### quant_analysis

```
1. 戦略概要 (200-300字)
2. 戦略の詳細 (ロジック + パラメータ)
3. バックテスト結果 (検証条件 + パフォーマンス指標 + 資産推移)
4. リスク分析 (ドローダウン + 感度分析)
5. 考察
6. まとめ
7. コード・データ
```

### market_report

```
1. 今週の市場サマリー (300-500字)
2. 株式市場 (米国市場 + 日本市場)
3. 為替市場
4. 経済指標
5. 来週の注目イベント
6. 参考データソース
```

### asset_management

```
1. はじめに (200-300字)
2. 基礎知識 (500-800字)
3. 実践ガイド (800-1200字)
4. 注意点・リスク (300-500字)
5. まとめ (200-400字)
6. 参考データソース
```

**severity**:
- 必須セクション欠落 → **high**
- セクション順序不正 → **medium**
- サブセクション欠落 → **medium**

## 3. フロントマターチェック (WR-FM)

記事の YAML フロントマターに必須項目が含まれているかを検証する。

### 共通必須項目

```
title, article_id, category, status
```

### カテゴリ別追加必須項目

| カテゴリ | 追加必須項目 |
|---------|-------------|
| stock_analysis | `symbol`, `analysis_date` |
| macro_economy | `indicators`, `regions` |
| investment_education | `topic`, `target_audience` |
| quant_analysis | `strategy`, `backtest_period` |
| market_report | `symbols`, `period` |
| asset_management | `theme`, `target_audience` |

**severity**:
- 共通必須項目の欠落 → **high**
- カテゴリ別必須項目の欠落 → **high**
- 推奨項目の欠落 → **low**

## 4. 信頼度別表現チェック (WR-CE)

claims.json の各主張の confidence と、記事内での表現パターンの対応を検証する。

### 信頼度→表現パターン対応表

| 信頼度 | 表現パターン | 例 |
|--------|-------------|-----|
| high / >= 0.8 / verified | 断定形 | 〜である、〜となった |
| medium / 0.5-0.79 | 引用形 | 〜とされている、〜と報告されている |
| low / < 0.5 / unverified | 伝聞形 | 〜と言われている（※要確認） |
| disputed | 両論併記 | 〜という見方と〜という見方がある |
| speculation | 可能性形 | 〜の可能性がある、〜と予想されている |

### 検証方法

1. claims.json から `accept` された主張を抽出
2. 各主張の `confidence` フィールドを取得
3. 記事内で該当主張がどの表現パターンで記述されているか判定
4. confidence と表現パターンの不一致を検出

**severity**:
- high confidence の主張に可能性形を使用（過度なヘッジ）→ **low**
- low confidence の主張に断定形を使用（根拠なき断定）→ **high**
- medium confidence の主張に断定形を使用 → **medium**

## 5. カテゴリ固有制約チェック (WR-CC)

各カテゴリのルールファイルに定義された固有制約を検証する。

### stock_analysis

| 制約 | チェック方法 |
|------|-------------|
| 目標株価の記載がない | 「目標株価」「TP」等のキーワード検索 |
| リスク要因の両面提示 | リスクセクションにポジティブ/ネガティブ両方の要素 |
| エグゼクティブサマリー 200-300字 | 文字数計測 |

### macro_economy

| 制約 | チェック方法 |
|------|-------------|
| シナリオ分析の存在 | 「楽観」「中立」「悲観」or 複数シナリオの提示 |
| 政治的中立性 | 「〜すべき」等の政策提言的表現の不在 |
| 通貨単位の明示 | 数値に USD/JPY/EUR 等の通貨表示 |

### investment_education

| 制約 | チェック方法 |
|------|-------------|
| FAQ セクション 3-5個 | Q&A の個数カウント |
| 専門用語の平易化 | 初出専門用語に説明が付いているか |
| 具体例の存在 | 各セクションに「例えば」「具体的には」等 |

### quant_analysis

| 制約 | チェック方法 |
|------|-------------|
| バックテスト条件の明示 | 期間、コスト、対象の記載 |
| 感度分析の存在 | 感度分析/ロバスト性検証セクション |
| 再現可能性 | ロジックの具体的記述、コード/GitHub リンク |

### market_report

| 制約 | チェック方法 |
|------|-------------|
| 週間騰落率の記載 | 主要指数に % 表記の騰落率 |
| 日付範囲が具体的 | 「先週」等の相対表現ではなく日付 |
| 数値フォーマット統一 | 小数点以下の桁数一貫性 |

### asset_management

| 制約 | チェック方法 |
|------|-------------|
| 末尾免責事項 | 記事末尾に「免責事項」を含む装飾なし段落 |
| curated_sources.json の存在 | ファイル存在チェック |
| 具体的数値例 | 「月3万円」「手取り25万円」等の現実的数値 |

**severity**:
- 必須制約の未達（シナリオ分析なし、FAQ なし等）→ **medium**
- 重要制約の未達（末尾免責なし、バックテスト条件不明示）→ **medium**
- 推奨制約の未達（具体例の不足等）→ **low**

## 6. カテゴリ別チェックリスト (WR-CL)

各カテゴリの references ファイル末尾に定義されたチェックリスト項目のうち、
他エージェントがカバーしていない項目を検証する。

### 他エージェントがカバー済み（スキップ対象）

以下は他エージェントの責務のため、writer_rules ではチェックしない:

| チェック項目 | カバーしているエージェント |
|-------------|------------------------|
| 禁止表現が含まれていない | compliance |
| 財務データに出典URLが埋め込まれている | fact |
| ディスクレーマーが記事末尾に1箇所 | compliance |
| マークダウン表が画像化されている | article-quality-standards チェック |
| 数値データにソースURLが埋め込まれている | fact |

### writer_rules でチェックする項目（カテゴリ別）

**stock_analysis**:
- エグゼクティブサマリーが200-300字で要点を押さえている
- バリュエーション表が画像化されている
- リスク要因セクション（両面提示）がある
- 買い/売り推奨・目標株価の記載がない

**macro_economy**:
- 概要が200-300字でトピックの背景を説明している
- シナリオ分析または複数の見方が提示されている
- 政策の評価が中立的か
- 通貨単位・時差が明示されている

**investment_education**:
- 「はじめに」で記事の価値と対象読者が明示されている
- 全ての専門用語が初出時に平易化されている
- 具体例（数値含む）が各セクションにある
- FAQ セクションが3-5個の Q&A を含む
- 「注意点・リスク」セクションがある
- ステップバイステップの実践ガイドがある

**quant_analysis**:
- 戦略のロジックが再現可能なレベルで記述されている
- バックテスト条件（期間、コスト、対象）が全て明示されている
- パフォーマンス指標の表が画像化されている
- 資産推移チャートが生成されている
- 感度分析でロバスト性を検証している

**market_report**:
- 市場サマリーが300-500字で週の概要を伝えている
- 週間騰落率が全ての主要指数に記載されている
- 経済指標の表が画像化されている
- 来週の注目イベントが記載されている
- 日付範囲が具体的に示されている
- 数値のフォーマット（小数点、%）が統一されている

**asset_management**:
- 「はじめに」で学べること・対象読者が明示されている
- 全ての専門用語が初出時に平易化されている
- 具体的な数値例（月3万円の積立など）がある
- ステップバイステップの実践ガイドがある
- 「注意点・リスク」セクションがある
- curated_sources.json が出力されている
- ソースURLが主要データに埋め込まれている

## 7. 参考データソースセクション (WR-SC の一部)

全カテゴリ共通で `## 参考データソース` セクションの存在と形式を検証する。

### 必須要素

- セクション見出し `## 参考データソース` が存在する
- データソースが箇条書きで列挙されている（最低1件）
- 各ソースにリンクが含まれている
- 分析期間の記載がある（「※ データは2026年3月時点のものです。」等）

**severity**:
- セクション自体の欠落 → **high**
- ソースリスト or 分析期間の欠落 → **medium**

---

## スコア計算式

```
score = 100 - (high x 15 + medium x 5 + low x 2)
```

スコアは 0-100 の範囲にクランプする。
