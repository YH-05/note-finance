# 共通執筆ルール

全カテゴリの金融記事で遵守すべきルール。

---

## 1. 信頼度別の表現ルール

リサーチで得た情報の検証ステータスと信頼度に応じて表現を使い分ける。事実と推測を混同しない。

> **注**: 現在の claims.json は `category/claim/evidence/impact` 構造で `verification_status` フィールドを持たない。ライターは evidence の質（公式データ/メディア報道/推測）から信頼度を判断し、以下の表現ルールを適用すること。

| 検証ステータス | 信頼度 | 表現パターン | 例 |
|--------------|--------|-------------|-----|
| verified | high | 断定形 | 〜である、〜となった |
| verified | medium | 引用形 | 〜とされている、〜と報告されている |
| unverified | - | 伝聞形 | 〜と言われている（※要確認） |
| disputed | - | 両論併記 | 〜という見方と〜という見方がある |
| speculation | - | 可能性形 | 〜の可能性がある、〜と予想されている |

decisions.json で `accept` された主張のみを記事に使用する。`reject` された主張は使わない。

## 2. 禁止表現と代替表現

金融商品取引法・投資助言規制に抵触する表現は使用禁止。検出した場合は代替表現に置き換える。

### 禁止表現リスト

| 禁止表現 | 理由 | 代替表現 |
|---------|------|---------|
| 買うべき | 投資助言に該当 | 注目に値する、検討に値する |
| 売るべき | 投資助言に該当 | リスクを考慮する必要がある |
| 見送るべき | 投資助言に該当 | 慎重な姿勢が求められる |
| おすすめ（銘柄） | 投資助言に該当 | 注目銘柄、一つの選択肢として |
| 今が買い時/売り時 | 投資助言に該当 | 検討に値するタイミング |
| 絶対に上がる/下がる | 断定的将来予測 | 〜の可能性が高い |
| 必ず儲かる | リターン保証示唆 | リターンが期待できる可能性がある |
| 損しない | リターン保証示唆 | リスクを抑えられる可能性がある |
| 間違いない | 断定的 | 可能性が高いと考えられる |
| 絶対に | 断定的 | 一般的には、多くの場合 |
| 必ず | 断定的 | 〜の傾向がある |
| 最強の | 誇張 | 優れた特徴を持つ |
| 一番良い | 誇張 | 多くの投資家に選ばれている |
| 推奨 | 投資助言に該当 | 一つの選択肢 |

### 注意表現（ヘッジ付きで使用可）

| 表現 | 判定 | 備考 |
|------|------|------|
| 〜と予想される | OK | 予想であることが明確 |
| 〜の可能性がある | OK | 不確実性を示す |
| 〜と考えられる | OK | 分析者の見解として適切 |
| 〜になるだろう | 注意 | 断定的に聞こえる可能性あり、文脈に注意 |

## 3. タイトル生成ルール（株投資ラボ共通）

**原則: 一発で内容が理解でき、読むメリットが伝わるタイトルにする。**

note.com はタイムライン表示・検索結果・SNS シェアなど「タイトルだけで読むかどうか決まる」場面が多い。読者がスクロール中でも「自分に関係ある」「読むと得する」と感じられる具体性が必須。

### 必須要件

| 要件 | 説明 |
|------|------|
| 具体的な対象 | 企業名・制度名・指標名など、何について書いているかが一語で伝わる |
| 読者メリット | 「分かる・学べる・比較できる・解決する」のいずれかが含意されている |
| 数字の活用 | 可能なら数字を入れる（「5つのポイント」「3年間の推移」「月3万円」など） |
| 長さ | **全角30-38字以内**（note.com のタイムラインで折り返さないサイズ） |
| 先頭15字 | スマホ表示で最初に目に入る部分に主要キーワードを配置 |

### 推奨パターン

| パターン | 例 |
|---------|-----|
| 「〇〇が分かる」型 | `新NISAの落とし穴が分かる｜運用前に知るべき5つの制度上限` |
| 「〇〇を比較」型 | `eMAXIS Slim vs SBI・V｜オルカン系ファンドをコストとリターンで徹底比較` |
| 数字＋結論型 | `月3万円の積立で2000万円をつくる｜現実的な利回りと期間シミュレーション` |
| 疑問解決型 | `利上げでなぜ株が下がる？金利と株価の関係をグラフで理解する` |
| 速報解説型 | `S&P500が過去最高値更新｜今週の米国市場を動かした3つの材料` |

### 禁止タイトルパターン

| 禁止 | 理由 | 修正例 |
|------|------|--------|
| `市場動向について` | 抽象的すぎて何が書いてあるか分からない | `3月の米国市場動向｜S&P500の上昇を支える3つのセクター` |
| `考えてみた` / `雑感` | 読者メリットが不明 | `〇〇を初心者向けに整理した｜知っておくべき3つのポイント` |
| 「！」「？」の連打 | 煽り感が出る。1タイトルにつき記号は1つまで | — |
| 絶対表現（「絶対儲かる」） | 投資助言規制違反 | § 2 禁止表現リスト参照 |
| ダッシュ記号（`ーー`, `——`） | § 6.5 記号の禁止参照 | 読点・全角コロン・縦棒に置換 |

### カテゴリ別の型

- **stock_analysis**: `{企業名}（{ティッカー}）の{切り口}｜{分かること}` 例: `テスラ（TSLA）を財務データで読む｜EV市場減速下の収益構造`
- **macro_economy**: `{指標/政策}を{どう捉えるか}｜{投資家への意味}` 例: `3月FOMCの据え置きが示すもの｜年内の利下げシナリオを再点検`
- **investment_education**: `{テーマ}を{初心者向け/図解で/ゼロから}理解する｜{読者の悩み解決}` 例: `PERとPBRの違いをゼロから理解する｜割高・割安の判断に使える指標`
- **asset_management**: `{目標/テーマ}｜{具体的な方法/数字}` 例: `新NISAで月5万円を20年運用する｜複利と取り崩し戦略をシミュレーション`
- **market_report**: `{期間}の{市場範囲}｜{最重要ポイント}` 例: `3/24週の米国市場｜エヌビディア決算と雇用統計を振り返る`
- **earnings**: `【🇺🇸米株決算】{企業名}（{ティッカー}）Q{四半期} {年} 決算プレビュー/レビュー`（earnings.md のフォーマット固定・サブタイトル付与不可）

### 生成手順

1. 記事の結論・最大の読者メリットを1フレーズで書き出す
2. そのフレーズに「具体的な対象」と「数字 or 比較軸」を付ける
3. 30-38字に収める（超過する場合はサブタイトルを `｜` で区切る）
4. `ーー` `——` `—` `--` が混入していないか確認（§ 6.5）
5. 煽り・投資助言・断定表現が含まれていないか確認（§ 2）

## 4. 記事末尾テンプレート（挨拶文＋免責事項）

記事本文の**一番最後は「挨拶文 → 免責事項」の2段構成で統一する。**

冒頭には免責事項を入れない。挨拶文は読者との関係性を育てる役割、免責事項は法的カバーの役割を担う。両方を常にセットで配置すること。

### 配置順序

```
（記事本文）
↓
## 参考データソース
（ソースリスト・分析期間）
↓
---
↓
（snippets/closing-greeting.md の全文: 挨拶文）
↓
---
↓
（snippets/disclaimer.md の全文: 免責事項）
```

### 挨拶文（必須・固定）

`snippets/closing-greeting.md` の全文を、区切り線の下に装飾なし段落として挿入する。改変禁止（句読点・絵文字・感嘆符をそのまま使う）。

```markdown
---

いつも読んでいただきありがとうございます！これからも株式投資・資産形成で役立つ記事をお届けします⭐️スキやフォローしていただけると励みになります！！
```

注意点:
- 挨拶文は**全カテゴリ共通**。earnings / stock_analysis / market_report 等でも省略しない
- 装飾（`>` 引用ブロック、`**` 太字、見出し `##`）を付けない
- 「⭐️」（U+2B50 U+FE0F）はそのまま残す。note.com のエディタは絵文字対応している

### 免責事項（必須・固定）

挨拶文の後に区切り線を挟み、`snippets/disclaimer.md` の全文を装飾なし段落として挿入する。

```markdown
---

免責事項: 本記事は一般的な情報提供を目的としており、特定の金融商品の売買を推奨するものではありません。投資には元本割れリスクがあります。株式、債券、投資信託、ETF等の金融商品は、市場の変動により価値が上下します。過去の実績は将来の運用成果を保証するものではありません。本記事に含まれる見通しや予測は、作成時点の情報に基づくものであり、将来の結果を保証するものではありません。NISA等の税制優遇制度の内容は、税制改正により変更される可能性があります。投資に関する最終決定は、ご自身の判断と責任において行ってください。
```

カテゴリ問わず同一の免責文を使用する。

### パーサーとの関係

note.com 投稿時に `scripts/note_publisher/markdown_parser.py` が以下を実行する:
- `## 参考データソース` セクションは投稿時に自動除去される
- 挨拶文は段落として保持される
- 免責事項は自動で末尾に再配置され、直前に区切り線1本が保証される

結果、note.com 上では「記事本文 → 挨拶文 → 免責事項」の順で表示される。

## 4. 記事品質ルール（note.com 特有）

note.com ではマークダウンの一部機能が正しくレンダリングされないため、以下を遵守する。

### 表の画像化

マークダウン表は note.com で崩れる。全ての表を `/generate-table-image` で PNG 画像に変換し、`![表タイトル](images/table_*.png)` で参照すること。

手順:
1. 表データの JSON を `.tmp/table_*.json` に作成
2. `uv run --with playwright python scripts/generate_table_image.py` で画像生成
3. 出力先: `articles/{category}/{slug}/images/table_*.png`

### チャートの画像化

データの可視化が必要な場合は `/generate-chart-image` で PNG 画像を生成する。テキストでデータを羅列するよりチャートのほうが読者の理解を助ける。

対象: 時系列推移、パフォーマンス比較、資産配分、シミュレーション結果など。

### ソース URL の埋め込み

数値データ・統計・専門家見解を引用する箇所には、ソース URL をマークダウンリンクとして埋め込む。読者が根拠を確認できるようにする。

```markdown
純資産総額が[10兆2,846億円に到達](https://example.com/source)しました。
CAPE比率は39.8に達しています（[出典: Motley Fool](https://example.com/source)）。
```

必須リンク対象:
- 具体的な数値データ（純資産総額、リターン、比率など）
- 統計・調査結果の引用
- 専門家・機関の見解の引用
- 公式発表・プレスリリースの参照

## 5. note.com 読者特性とモバイル最適化

note.com の読者はスマホで隙間時間に読む人が大半（70%以上）。最初の数行で継続/離脱を判断する。この特性を踏まえた書き方が必要。

### モバイル最適化

| 要素 | 目安 |
|------|------|
| 1段落の長さ | スマホで3-4行（80-120文字） |
| 見出し間隔 | 300-500文字ごとに見出しを配置 |
| 1文の長さ | 30-50文字（読者レベルに応じて調整） |
| 記事全体の長さ | **8000-10000字**（カテゴリ別ルールで上書き可） |

### 改行と空行のルール

note.com では段落間に空行がないと文章が詰まって見える。元の文章で改行があった箇所は、note 本文では**1行空け**（空行を1つ挿入）にすること。これによりスマホでの可読性が大幅に向上する。

```markdown
# 悪い例（改行のみ）
投資信託は長期運用に向いています。
信託報酬が低いファンドを選ぶことが重要です。

# 良い例（1行空け）
投資信託は長期運用に向いています。

信託報酬が低いファンドを選ぶことが重要です。
```

### 冒頭のインパクト

最初の3行で「この記事を読む価値」を伝える。問題提起 → 解決の示唆 → 読者にとっての意味、の順が効果的。

### 視覚的な読みやすさ

- 長い段落を避け、箇条書き・表・チャートを積極的に使う
- 見出しは内容を端的に示す（「財務分析」より「売上高は前年比 20% 増」）
- テキストの合間に画像/チャートを配置して視覚的変化をつける

## 6. ターゲット読者別の文体調整

meta.yaml の `target_audience` に基づいて文体を調整する。

### beginner（初心者）

- 専門用語には初出時に必ず説明を付ける（括弧書き、直後の補足文、例示のいずれか）
- 前提知識を仮定しない
- 具体例を多用する
- 1文は30-40文字目安

**専門用語の平易化パターン**:
1. 括弧書き: 「インデックスファンド（市場全体の値動きに連動する投資信託）」
2. 直後の補足: 「リバランスを行います。リバランスとは、値動きによってずれた資産配分を元の比率に戻す作業のことです。」
3. 例示: 「ドルコスト平均法、つまり毎月同じ金額を積み立てる方法」

2回目以降は説明不要。

### intermediate（中級者）

- 基本用語（PER、ROE、インデックス等）は説明不要
- 分析の根拠を明示する
- データの解釈を丁寧に書く
- 1文は40-50文字目安

### advanced（上級者）

- 専門用語をそのまま使用可
- 詳細なデータ分析を含める
- 簡潔な表現を心がける
- 1文は40-60文字目安

## 6.5. 文体（株投資ラボ共通）

**全記事をです・ます調（敬体）で執筆すること。**

このスキルが生成する記事はすべて株投資ラボ（note.com）向けである。読者との距離感を適切に保つため、常体（だ・である調）は使用しない。

### 適用ルール

| 対象 | ルール |
|------|--------|
| 本文の文末 | **ですます調**（〜です。〜ます。〜ました。〜います。） |
| 見出し（## / ###） | 体言止めでよい（文体変換不要） |
| 引用符内（「〜」） | 原文どおりでよい |
| 数値・固有名詞 | 変換不要 |
| 免責事項 | ですます調で統一 |

### 変換パターン早見表

| 常体（禁止） | 敬体（使用する） |
|------------|----------------|
| 〜だ。 | 〜です。 |
| 〜である。 | 〜です。 |
| 〜ある。 | 〜あります。 |
| 〜いる。 | 〜います。 |
| 〜した。 | 〜しました。 |
| 〜する。 | 〜します。 |
| 〜なる。 | 〜なります。 |
| 〜できる。 | 〜できます。 |
| 〜れた。 | 〜れました。 |
| 〜ている。 | 〜ています。 |
| 〜てきた。 | 〜てきました。 |
| 〜だろう。 | 〜でしょう。 |
| 〜ない。 | 〜ません。 / 〜ありません。 |
| 〜に尽きる。 | 〜に尽きます。 |

接続部（〜であり、〜しており、〜となり）は文末でないため変換不要。

### 記号の禁止（株投資ラボ共通）

**ダッシュ（長音連続・em dash 連続）は使用禁止。**

note.com 向け記事では、以下の記号を使わずに読点「、」や改行・かっこ書きなどで言い換えること。ダッシュは日本語記事では威圧的・翻訳調に見え、株投資ラボの読者層（個人投資家・初心者〜中級者）に合わないため排除する。

| 禁止記号 | 例 | 代替 |
|---------|-----|------|
| `ーー` | 「今月の相場はーー非常に不安定でした」 | 読点で言い換え「今月の相場は、非常に不安定でした」 |
| `——` | 「リスク——とくに地政学リスク——が顕在化」 | かっこ書き「リスク（とくに地政学リスク）が顕在化」 |
| `—` (em dash 単体) | 「結論—売買は慎重に」 | 読点または文の分割「結論としては、売買は慎重に行うことをおすすめします」 |
| `--` | 「注目ポイント--決算発表日」 | コロン置換「注目ポイント: 決算発表日」 |

カテゴリ別テンプレート内（stock-analysis.md の「リスク要因 — 必ず両面を提示」等）でメタ記述として使っている箇所は、**本文生成時に引き継がない**。テンプレ文中の「—」は実装メモであり、記事には出力しないこと。

見出し内のタイトルサブタイトル区切りとして ` — ` を使う場面（例: earnings カテゴリで `タイトル — サブタイトル`）も、原則全角スペース＋読点や全角コロンで代替する。どうしてもサブタイトルを視覚的に分離したい場合は `｜`（全角縦棒）を使う。

## 7. データソースの明示

記事末尾に「参考データソース」セクションを設け、使用したデータの出典を列挙する。分析期間も明示する。

```markdown
## 参考データソース

- [Yahoo Finance](https://finance.yahoo.com/) — 株価・財務データ
- [SEC EDGAR](https://www.sec.gov/edgar/) — 10-K/10-Q 報告書
- [日本銀行](https://www.boj.or.jp/) — 金融政策・統計データ

※ データは2026年3月時点のものです。
```

## 8. 構成評価の基準

記事の構成は以下5つの観点で評価される。批評・修正時にこの基準を意識する。

| 観点 | 重み | ポイント |
|------|------|---------|
| 導入部 (Introduction) | 20% | フックの効果、問題提起の明確さ、読む価値の提示 |
| 論理展開 (Flow) | 25% | 段階的説明、セクション間の遷移、論点の一貫性 |
| セクション構成 (Sections) | 25% | 見出しの明確さ、階層構造、バランス |
| 結論 (Conclusion) | 15% | 要約の的確さ、読者への示唆、次のアクション |
| 読みやすさ (Readability) | 15% | 文の長さ、段落の長さ、専門用語の説明 |

## 9. 共通チェックリスト

全カテゴリで適用する共通チェック項目。カテゴリ別ルールのチェックリストはカテゴリ固有の項目のみを記載し、以下と重複させない。

### タイトル（§ 3）
- [ ] タイトルだけで記事内容が一発で理解できる（抽象語のみで終わっていない）
- [ ] 読者メリット（分かる・学べる・比較できる・解決する）が含意されている
- [ ] 全角30-38字以内に収まっている
- [ ] 煽り記号（！！！や？？？の連打）・投資助言的断定が含まれていない
- [ ] ダッシュ（`ーー` `——` `—` `--`）がタイトルに使われていない

### 文字数・構成
