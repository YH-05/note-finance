# 共通執筆ルール

全カテゴリの金融記事で遵守すべきルール。

---

## 1. 信頼度別の表現ルール

リサーチで得た情報の検証ステータスと信頼度に応じて表現を使い分ける。事実と推測を混同しない。

> **注**: 現在の claims.json は `category/claim/evidence/impact` 構造で `verification_status` フィールドを持たない。ライターは evidence の質（公式データ/メディア報道/推測）から信頼度を判断し、以下の表現ルールを適用すること。

| 検証ステータス | 信頼度 | 表現パターン | 例 |
|--------------|--------|-------------|-----|
| verified | high | 断定形 | 〜である、〜となった |
| verified | medium | 引用形 | 〜とされている、〜と報告されている |
| unverified | - | 伝聞形 | 〜と言われている（※要確認） |
| disputed | - | 両論併記 | 〜という見方と〜という見方がある |
| speculation | - | 可能性形 | 〜の可能性がある、〜と予想されている |

decisions.json で `accept` された主張のみを記事に使用する。`reject` された主張は使わない。

## 2. 禁止表現と代替表現

金融商品取引法・投資助言規制に抵触する表現は使用禁止。検出した場合は代替表現に置き換える。

### 禁止表現リスト

| 禁止表現 | 理由 | 代替表現 |
|---------|------|---------|
| 買うべき | 投資助言に該当 | 注目に値する、検討に値する |
| 売るべき | 投資助言に該当 | リスクを考慮する必要がある |
| 見送るべき | 投資助言に該当 | 慎重な姿勢が求められる |
| おすすめ（銘柄） | 投資助言に該当 | 注目銘柄、一つの選択肢として |
| 今が買い時/売り時 | 投資助言に該当 | 検討に値するタイミング |
| 絶対に上がる/下がる | 断定的将来予測 | 〜の可能性が高い |
| 必ず儲かる | リターン保証示唆 | リターンが期待できる可能性がある |
| 損しない | リターン保証示唆 | リスクを抑えられる可能性がある |
| 間違いない | 断定的 | 可能性が高いと考えられる |
| 絶対に | 断定的 | 一般的には、多くの場合 |
| 必ず | 断定的 | 〜の傾向がある |
| 最強の | 誇張 | 優れた特徴を持つ |
| 一番良い | 誇張 | 多くの投資家に選ばれている |
| 推奨 | 投資助言に該当 | 一つの選択肢 |

### 注意表現（ヘッジ付きで使用可）

| 表現 | 判定 | 備考 |
|------|------|------|
| 〜と予想される | OK | 予想であることが明確 |
| 〜の可能性がある | OK | 不確実性を示す |
| 〜と考えられる | OK | 分析者の見解として適切 |
| 〜になるだろう | 注意 | 断定的に聞こえる可能性あり、文脈に注意 |

## 3. 免責事項

記事本文の**一番最後に1箇所だけ**挿入する。冒頭には入れない。

挿入位置: 参考データソースセクションの後、区切り線の下に配置する。装飾なし（引用ブロック `>` や太字 `**` を使わない）。

```markdown
---

免責事項: 本記事は一般的な情報提供を目的としており、特定の金融商品の売買を推奨するものではありません。投資には元本割れリスクがあります。株式、債券、投資信託、ETF等の金融商品は、市場の変動により価値が上下します。過去の実績は将来の運用成果を保証するものではありません。本記事に含まれる見通しや予測は、作成時点の情報に基づくものであり、将来の結果を保証するものではありません。NISA等の税制優遇制度の内容は、税制改正により変更される可能性があります。投資に関する最終決定は、ご自身の判断と責任において行ってください。
```

全文は `snippets/disclaimer.md` を参照。カテゴリ問わず同一の免責文を使用する。

## 4. 記事品質ルール（note.com 特有）

note.com ではマークダウンの一部機能が正しくレンダリングされないため、以下を遵守する。

### 表の画像化

マークダウン表は note.com で崩れる。全ての表を `/generate-table-image` で PNG 画像に変換し、`![表タイトル](images/table_*.png)` で参照すること。

手順:
1. 表データの JSON を `.tmp/table_*.json` に作成
2. `uv run --with playwright python scripts/generate_table_image.py` で画像生成
3. 出力先: `articles/{category}/{slug}/images/table_*.png`

### チャートの画像化

データの可視化が必要な場合は `/generate-chart-image` で PNG 画像を生成する。テキストでデータを羅列するよりチャートのほうが読者の理解を助ける。

対象: 時系列推移、パフォーマンス比較、資産配分、シミュレーション結果など。

### ソース URL の埋め込み

数値データ・統計・専門家見解を引用する箇所には、ソース URL をマークダウンリンクとして埋め込む。読者が根拠を確認できるようにする。

```markdown
純資産総額が[10兆2,846億円に到達](https://example.com/source)しました。
CAPE比率は39.8に達しています（[出典: Motley Fool](https://example.com/source)）。
```

必須リンク対象:
- 具体的な数値データ（純資産総額、リターン、比率など）
- 統計・調査結果の引用
- 専門家・機関の見解の引用
- 公式発表・プレスリリースの参照

## 5. note.com 読者特性とモバイル最適化

note.com の読者はスマホで隙間時間に読む人が大半（70%以上）。最初の数行で継続/離脱を判断する。この特性を踏まえた書き方が必要。

### モバイル最適化

| 要素 | 目安 |
|------|------|
| 1段落の長さ | スマホで3-4行（80-120文字） |
| 見出し間隔 | 300-500文字ごとに見出しを配置 |
| 1文の長さ | 30-50文字（読者レベルに応じて調整） |
| 記事全体の長さ | **8000-10000字**（カテゴリ別ルールで上書き可） |

### 改行と空行のルール

note.com では段落間に空行がないと文章が詰まって見える。元の文章で改行があった箇所は、note 本文では**1行空け**（空行を1つ挿入）にすること。これによりスマホでの可読性が大幅に向上する。

```markdown
# 悪い例（改行のみ）
投資信託は長期運用に向いています。
信託報酬が低いファンドを選ぶことが重要です。

# 良い例（1行空け）
投資信託は長期運用に向いています。

信託報酬が低いファンドを選ぶことが重要です。
```

### 冒頭のインパクト

最初の3行で「この記事を読む価値」を伝える。問題提起 → 解決の示唆 → 読者にとっての意味、の順が効果的。

### 視覚的な読みやすさ

- 長い段落を避け、箇条書き・表・チャートを積極的に使う
- 見出しは内容を端的に示す（「財務分析」より「売上高は前年比 20% 増」）
- テキストの合間に画像/チャートを配置して視覚的変化をつける

## 6. ターゲット読者別の文体調整

meta.yaml の `target_audience` に基づいて文体を調整する。

### beginner（初心者）

- 専門用語には初出時に必ず説明を付ける（括弧書き、直後の補足文、例示のいずれか）
- 前提知識を仮定しない
- 具体例を多用する
- 1文は30-40文字目安

**専門用語の平易化パターン**:
1. 括弧書き: 「インデックスファンド（市場全体の値動きに連動する投資信託）」
2. 直後の補足: 「リバランスを行います。リバランスとは、値動きによってずれた資産配分を元の比率に戻す作業のことです。」
3. 例示: 「ドルコスト平均法、つまり毎月同じ金額を積み立てる方法」

2回目以降は説明不要。

### intermediate（中級者）

- 基本用語（PER、ROE、インデックス等）は説明不要
- 分析の根拠を明示する
- データの解釈を丁寧に書く
- 1文は40-50文字目安

### advanced（上級者）

- 専門用語をそのまま使用可
- 詳細なデータ分析を含める
- 簡潔な表現を心がける
- 1文は40-60文字目安

## 7. データソースの明示

記事末尾に「参考データソース」セクションを設け、使用したデータの出典を列挙する。分析期間も明示する。

```markdown
## 参考データソース

- [Yahoo Finance](https://finance.yahoo.com/) — 株価・財務データ
- [SEC EDGAR](https://www.sec.gov/edgar/) — 10-K/10-Q 報告書
- [日本銀行](https://www.boj.or.jp/) — 金融政策・統計データ

※ データは2026年3月時点のものです。
```

## 8. 構成評価の基準

記事の構成は以下5つの観点で評価される。批評・修正時にこの基準を意識する。

| 観点 | 重み | ポイント |
|------|------|---------|
| 導入部 (Introduction) | 20% | フックの効果、問題提起の明確さ、読む価値の提示 |
| 論理展開 (Flow) | 25% | 段階的説明、セクション間の遷移、論点の一貫性 |
| セクション構成 (Sections) | 25% | 見出しの明確さ、階層構造、バランス |
| 結論 (Conclusion) | 15% | 要約の的確さ、読者への示唆、次のアクション |
| 読みやすさ (Readability) | 15% | 文の長さ、段落の長さ、専門用語の説明 |

## 9. 共通チェックリスト

全カテゴリで適用する共通チェック項目。カテゴリ別ルールのチェックリストはカテゴリ固有の項目のみを記載し、以下と重複させない。

### 文字数・構成
- [ ] 文字数がカテゴリ別ルールで指定された範囲内（デフォルト: 8000-10000字）
- [ ] 段落間に空行が入っている（note.com の改行ルール準拠）
- [ ] 見出し間隔が 300-500字以内

### コンプライアンス
- [ ] 禁止表現が含まれていない（共通 + カテゴリ追加分）
- [ ] 免責事項（`snippets/disclaimer.md` の全文）が記事末尾に1箇所だけ挿入されている
- [ ] 免責事項が冒頭に入っていない
- [ ] 免責事項に装飾（`>` 引用ブロック、`**` 太字）が付いていない

### データ・ソース
- [ ] 主要な数値データにソースURLがマークダウンリンクで埋め込まれている
- [ ] マークダウン表が残っていない（全て `/generate-table-image` で画像化済み）
- [ ] 末尾に「参考データソース」セクションがある
- [ ] データの時点が明示されている（「2026年3月時点」等）
